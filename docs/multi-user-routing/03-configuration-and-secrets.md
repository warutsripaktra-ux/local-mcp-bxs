# Configuration and Secrets

## Ownership

| Value | Central host | User host | Secret |
|---|---:|---:|---:|
| `CONTROL_PLANE_TUNNEL_ID` | yes | no | identifier |
| `CONTROL_PLANE_API_KEY` | yes | never | yes |
| `TUNNEL_CLIENT_BIN`, `TUNNEL_PROFILE` | yes | no | no |
| OAuth issuer and canonical resource/audience | yes | no | no |
| OAuth client secret, if required | yes | no | yes |
| Router registry/database credential | yes | no | yes |
| Router Agent URL | no | yes | no |
| Pairing code | temporary | temporary | yes, one-time |
| Device credential | verifier only | yes | yes |
| Project/tool policy | no | yes | sensitive configuration |

Never copy Tunnel credentials to user machines. Never use a Tunnel API key as user or device identity.

## Current central variables

Implemented now:

```dotenv
CONTROL_PLANE_TUNNEL_ID=tunnel_replace_me
CONTROL_PLANE_API_KEY=sk_replace_me
TUNNEL_CLIENT_BIN=/absolute/path/to/tunnel-client
TUNNEL_PROFILE=futuremakers-gateway
```

Optional test-only override names consumed by `scripts/run-router.cjs`:

```dotenv
ROUTER_ISSUER=https://idp.example.com/
ROUTER_AUDIENCE=local-gateway-mcp
ROUTER_JWKS_URL=https://idp.example.com/jwks.json
ROUTER_DEMO=1
```

These names are not the production contract. `ROUTER_DEMO=1` trusts arbitrary bearer values and must remain unreachable from production.

Production names consumed by `scripts/run-router.cjs`:

```dotenv
ROUTER_MCP_HOST=127.0.0.1
ROUTER_MCP_PORT=8787
ROUTER_AGENT_HOST=private-hostname-or-ip
ROUTER_AGENT_PORT=8788
OIDC_ISSUER=https://idp.example.com/
OIDC_AUDIENCE=https://mcp.example.com/mcp
ROUTER_REGISTRY_FILE=/Users/your-user/.futuremakers-gateway/agents.json # macOS
ROUTER_CREDENTIAL_FILE=/Users/your-user/.futuremakers-gateway/credentials.json # macOS
# Linux alternative:
# ROUTER_REGISTRY_FILE=/var/lib/futuremakers-gateway/agents.json
# ROUTER_CREDENTIAL_FILE=/var/lib/futuremakers-gateway/credentials.json
AUDIT_RETENTION_DAYS=90
AGENT_HEARTBEAT_INTERVAL_MS=15000
AGENT_OFFLINE_AFTER_MS=45000
```

`OIDC_ISSUER` must exactly match the provider discovery metadata and token `iss`, including path, case, port, and trailing slash. `OIDC_AUDIENCE` is the canonical public HTTPS MCP resource seen by ChatGPT; use the same exact value for protected-resource metadata and token audience/resource validation.

Production discovers `jwks_uri` from the provider-published OAuth/OIDC metadata. Do not require a separately configured JWKS URL in production. Use an established IdP and keep authorization-server implementation outside this repository.

## Current Agent variables

Requested whole-machine defaults on macOS/Linux:

```dotenv
PROJECT_ROOTS=/
ALLOW_READ=true
ALLOW_WRITE=true
ALLOW_PROCESS=true
ALLOWED_COMMANDS=*
REQUIRE_CONFIRMATION_FOR=project:write,project:process
```

User-facing Agent setup:

`pnpm run agent` discovers the Router OAuth bootstrap configuration, opens a
PKCE login, provisions the device, and stores the resulting credential in the
OS keychain. User machines do not need `DEVICE_CREDENTIAL_ID`,
`DEVICE_CREDENTIAL_SECRET`, `AGENT_ISSUER`, or `AGENT_SUB` in `.env`.
`ROUTER_AGENT_URL` is only a deployment/package override; the distributed
agent should contain the organization's Router URL.

Do not persist a pairing code or OAuth access token. Exchange the OAuth code
for a device credential during `pnpm run agent`, then store only that device
credential in the OS secret store where practical.

`DC_AGENT_POLICY` and `DC_REMOTE_DEVICE` are generated by `run-agent`; users must not set them manually.

## Whole-machine semantics

`PROJECT_ROOTS=/` authorizes paths under the filesystem root, subject to OS permissions. It does not bypass:

- OAuth user-to-agent ownership.
- Device authentication.
- Tool scope and argument validation.
- `ALLOWED_COMMANDS`.
- Write/process confirmation.
- macOS privacy/Full Disk Access controls.

Windows requires explicit drive roots, for example `C:\` and additional drives. Define parsing/tests before claiming Windows support.

## Validation rules

Central startup must fail when:

- Tunnel ID/key is missing for tunnel mode.
- Router binds a non-loopback MCP address without explicit configuration.
- OAuth issuer/audience is missing in production mode.
- OAuth discovery fails, metadata issuer differs from `OIDC_ISSUER`, or `jwks_uri` is invalid.
- `OIDC_AUDIENCE` is not the configured canonical public HTTPS MCP resource.
- Registry/audit store is unavailable.
- TLS is absent on cross-machine Agent endpoints.

Agent startup must fail when:

- Read/write is enabled with no roots.
- Process is enabled with an empty command allowlist.
- Router URL is not HTTPS outside local tests.
- Device credential is absent after OAuth bootstrap.
- State/credential file permissions are broader than owner-only where enforceable.

## Storage rules

- Keep local configuration in ignored `.env`; do not create `.env.local`.
- Keep raw secrets out of Git, plugin archives, logs, metrics, support bundles, and error messages.
- Store pairing codes/device verifiers as hashes on the Router.
- Restrict central state files to the service account.
- Redact `Authorization`, cookies, query tokens, pairing codes, and device credentials.

## Rotation

| Credential | Rotation trigger | Required action |
|---|---|---|
| Tunnel API key | scheduled or suspected exposure | create new runtime key, restart tunnel, revoke old key |
| OAuth keys | IdP rotation | refresh JWKS; reject retired keys after cache policy |
| Device credential | scheduled, replacement, lost machine | issue new version, fence/revoke old version |
| Pairing code | expiry/use | delete or mark consumed immediately |

## Template policy

`.env.example` intentionally shows requested whole-machine defaults. README and startup output must display a high-risk warning. Production onboarding should generate per-user `.env`/state without copying central secrets.
